# DSPi managed configuration and runtime

`Dspi.Software` targets .NET 8 and has no external packages. Put the matching `dspi-host.dll` beside the application (or in its native library search path). Build the native engine first, then run the checks with:

```
dotnet run --project managed/Dspi.Software.Tests
```

`EngineConfiguration` keeps eight physical input slots, eight output slots, 64 crosspoints in `input * 8 + output` order, ten descriptive PEQ bands per channel and four crossover slots per output. `InputCount` and `OutputCount` select the actual device topology. Active masks and routes must reference available channels. Upmix requires two physical inputs at no more than 48 kHz and exposes five matrix sources. Inputs have preamp, delay and PEQ; output slots also provide gain, enable/mute, crossover and limiter. Filter wire type 11 preserves the original frequency/Q and target frequency (`Gain`)/Q (`TargetQ`) values. Flat/bypassed bands remain in saved documents.

`PresetStore.Save` validates before writing, flushes a temporary sibling file, then replaces the destination. `Load` returns a newly validated configuration; apply it through `NativeSession.Apply` to retain the previous session on validation/preparation failure. Schema versions from the future, nonfinite values, unknown managed fields and invalid topology are rejected. `ImportDspi`/`ImportDspiJson` return a configuration and explicit warnings for unsupported hardware IO, input selection/persistence controls and outputs beyond eight. Inspect and display these warnings before using an imported preset. Imported limiter settings are audio processing controls and are retained. Presets do not set Windows devices or GPIOs.

Console presets containing twelve EQ slots can be imported when slots 11 onward are flat or bypassed; every omitted inactive slot is reported. Active EQ beyond ten is rejected. Linked limiter group members must use identical enable, threshold and release settings, matching the firmware's linked controls. `VolumeDb` is the user/listening volume and follows the native firmware's downward whole-decibel quantization and silence at -60 dB. `MasterVolumeDb` is an independent output trim from -128 to +12 dB, with -128 as exact mute; changing this trim preserves the listening volume used to calibrate loudness. DSPi imports retain both levels separately; hardware persistence modes are reported as unsupported.

`NativeSession` prepares each graph outside processing, then submits it for the native 10 ms fade down/switch/fade up. Successful submit transfers graph ownership; failed preparation/submit leaves `CurrentConfiguration` unchanged. `CurrentConfiguration` is a defensive copy of the latest accepted configuration (the fade may still be running). Rate and topology changes require a new session. One audio thread calls `Process` with separate interleaved input/output arrays; any frame count is accepted. One control thread calls `Apply` and `ReadMeters`. Meter peaks and clip bits are read and reset, with input bits 0–7 and output bits 8–15; meter polling also reclaims retired graphs on the control thread. Dispose after stopping processing. Processing runs native DSP with no generated audio or artificial meters.

Global bypass retains matrix routes for physical inputs, input/output gains and delays, global volume, output enable/mute and limiters. It omits PEQ, crossover and effects including virtual upmix source generation. Per-channel bypass omits PEQ only and retains crossover. All bypassed settings remain intact in JSON and return when bypass is disabled.
